# Modelling Autonomous Trajectories Across Musical Landscapes

How can we model actions taken by an agent inside a fl studio project?

first thing i notice is that usually you work on a functional unit of sound or object:

- vocals might be a single element or an object with lead, adlibs, harmonies, backing;
- drums are composed or multiple instruments;
- a producer or engineer might view a group of instruments or an arragement section as an object and think about that horizontally in a playlist, even though vertically the group can be separated into clips;
- on the other hand in the mixer an object might be broken into vertical slices of processing and horizontal slices of tracks;
- when you compose a piano roll with all the midis present in a composition/project all instruments converge into a single unit;
- a single instrument is expanded into multiple units which can be structured based on function or logic and recognized as patterns of movement across a tonal space.
- a processing chain can be seen as a graph of vertical and horizontal relationships.
...
this complexity is represented in different dimensions across the landscape. we can understand these concepts.

usually an agent in this landscape attempts to reach a state where the configuration of objects matches some idea.

for a skilled producer/engineer that usually involves a lot of actions, such as adjusting parameters, tweaking effects, and fine-tuning the sound of a specific object, a drop, verse, bassline, etc, after that, it starts to consider relationships which should be created or that exist, which involve how that object interacts with other objects in the project. we can also decompose an object into components, for example, an object might be balanced along another object, but the reverb component of the latter object might create some issues with the former object.

changes made to one object can affect the overall mix and vice versa, this evokes a sense of hierachical interconnectivity we can model:

- objects are organized into layers, where some objects are considered primary and others secondary, some might have a function of rhythm while others work for harmonic, melodic, or atmospheric functionalities, so on..., allowing for a structured approach to represent different layouts of objective, subjective and stylistic configurations.

This hierarchical model can help in prioritizing which objects to focus on first or to prioritize when some object parameter needs adjustment relative to other objects, and how to manage their interactions within the project.

By modeling these actions in a systematic way, we can better understand the workflow of a producer/engineer and optimize the creative process within a FL Studio project. we can consider the process a trajectory in which we are attempting to reduce an axis representing the roughness of the sound, while also augmenting an axis representing the overall objective optimizations, balance, aesthetic matching and cohesion of the mix.

aesthetics are a big part of this process, as the agent's decisions are often guided by subjective preferences and artistic vision, or by a set of predefined rules or references.

we are working with a lot of parameters: midi notes, arrangement cells and structures, generators, effects, spectral and dynamic relationships, phase alignments or timing adjustments, and more. Each of these parameters can be adjusted within an object or across objects to achieve the desired sound.

here we discuss how to model this landscape and its objective and subjective space of actions, how to optimize the forces in this field, and how to coordinate objects into compositions.

we can leverage a lot of concepts from graphs, html, and dynamic forms of structural thought to create an agentic framework of reasoning and action designed for music production and audio processing workflows using fl studio.
