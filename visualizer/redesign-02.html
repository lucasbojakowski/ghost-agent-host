The change sequence

Six boundaries, composed in order.

Each step creates a small stable interface for the next. Host facts stay in core, native loading stays in host, and the editor remains a controller rather than an audio engine.

  1. 01 · Host truth

    The DAW owns time and format.

    Activation now receives the DAW sample rate and block size. Every process call snapshots tempo, song time, beat, bar, time signature, playback, recording, and loop state into lock-free atomics.

  2. 02 · Capture

    File import and live recording become peers.

    A bounded, preallocated stereo recorder arms from the UI and writes on the audio thread. The selected tap is acknowledged with its actual key, so inactive edge requests report their Output fallback honestly.

  3. 03 · Graph

    Topology stops being decoration.

    Users can start empty or apply EQ, compressor, or combined presets; then create, remove, reorder, reclassify, bypass, and assign nodes. Capture taps are regenerated from the topology.

  4. 04 · Native child

    Discovery turns into instantiation.

    The host splits each child into a main-thread owner and a sendable audio handle. Public parameters, state streams, event queues, transport, audio ports, and Win32 child windows are bridged through explicit adapters.

  5. 05 · Workflow

    Capture, Analyze, Propose no longer share a pulse.

    Independent receivers and stage state prevent scanner activity from animating the workflow. Workflow, Analyzer, and Routing are distinct views with isolated scroll areas and collapsible discovery.

  6. 06 · Presentation

    Wire schemas stay behind the glass.

    The proposal reader surfaces intent, confidence, audible actions, expected change, cautions, and verification. Schema versions and system fields remain available to machines, not foregrounded to musicians.

Runtime architecture

One plugin, three timing domains.

Audio thread

Bounded and deterministic

  • • copy or process stereo buffers
  • • forward CLAP transport
  • • capture selected graph edge
  • • read atomic bypass mask
  • • no locks, files, scans, or allocation

Main thread

Owns native lifecycle

  • • instantiate and destroy children
  • • activate graph revisions
  • • save and restore nested state
  • • parent child GUI windows
  • • request host restarts

Worker threads

Slow work stays explicit

  • • decode imported media
  • • analyze captured material
  • • scan plug-in directories
  • • run mocked proposal transport
  • • return correlated stage results

Explicit acceptance boundary

Honest edges, not hidden gaps.

The core loop is implemented. These remaining items depend on broader compatibility work or new domain compilers and are deliberately recorded rather than implied complete.

  • Dynamic latency aggregation

    Child latency is not yet summed and exposed through the outer clap.latency extension.

  • Live semantic parameter application

    The adapter can enqueue child parameter events, but proposals remain staged for user review.

  • Four specialized compilers

    Saturation, reverb, limiter, and multiband nodes are typed; their dedicated context contracts remain future work.

  • Proprietary host matrix

    FL Studio reload, vendor-specific GUI behavior, and a representative third-party CLAP set require Windows acceptance testing.
