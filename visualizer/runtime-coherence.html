Architecture repaired at the ownership boundaries

Four drifting state owners became one coherent runtime.

The fix was not a collection of widget patches. Ghost now has a revisioned project document, a persistent editor session, an explicit main-thread controller, and bounded realtime control. Graph activation, child windows, transport, and proposal application all cross named boundaries.

The three ordering invariants

  1. 01

    Commit, then restart. The pending revision exists before the DAW can reactivate.

  2. 02

    Preview, then transact. Incomplete semantic mappings fail closed.

  3. 03

    Own windows independently. Closing egui cannot destroy a detached child.

02 / implementation trajectory

Repair the cause before polishing the symptom.

Every slice established a boundary consumed by the next. UX work arrived after ownership and ordering were trustworthy.

  1. SLICE 01

    Revision ownership

    Removed clone/writeback, added monotonic commits, and made active versus pending observable across load and activate.

  2. SLICE 02

    Lifetime repair

  3. SLICE 03

    Host affordances

    Routed GUI, params, state, latency, timers, thread checks, logging, restart, process, and callbacks.

  4. SLICE 04

    Transactional proposals

    Compiled semantic intent into strict concrete patches, applied or flushed them, acknowledged reality, persisted state, and enabled Undo.

  5. SLICE 05

    UX and evidence

    Added responsive layouts, freshness, bounded text, review states, deterministic acceptance, and an honest manual boundary.

03 / proposal delivery

A proposal is evidence. Apply is a transaction.

01

Preview

Semantic intent stays inert.

02

Compile

Bind node, revision, ID, range, unit, prior value, confidence.

03

Review

Any required ambiguity disables Apply.

04

Deliver

Block boundary or stopped-audio params.flush.

05

Acknowledge

Save child state, dirty project, verify feedback, retain inverse.

Successful transaction states

Preview → Queued → Applied → Verified. Undo creates a new transaction from acknowledged previous values rather than assuming the preview snapshot stayed current.

Fail-closed states

Mapping incomplete or Failed names graph mismatch, missing node, ambiguity, range rejection, or child rejection. Silent partial application is not a mode.
